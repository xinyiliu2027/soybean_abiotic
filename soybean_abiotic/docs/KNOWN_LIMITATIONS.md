# Known limitations and changes

## 整理范围

拆分脚本、统一 UTF-8/LF、参数化项目根路径并添加索引。原始提取正文保存在 `source_text/`，修改逐项记录于 `source_manifest.json`。文档中的“完整”“修复”“不要修改”等文字属于原始注释，不能视为本仓库已经通过复现的保证。

## 明确修复

- 图2首段在 treatment 循环结束处缺少 `}`，补齐闭合，避免后面的 PI 脚本被意外嵌入循环。
- 图3 CK 脚本结尾将残留的 `output_dir` 改为该脚本实际使用的 `OUT`。
- 图1删除无助于已建样本列表的 `rm(SA1)`，临时对象清理增加存在性判断；出现多个 DoubletFinder 分类列时明确报错，避免隐式选择。
- 图3候选分析不再固定读取某次历史运行目录，而要求显式设置阶段 DEG 文件。
- velocity 增加命令行输入/输出路径、重复匹配键和元数据列冲突检查、有限 UMAP 坐标检查，并在缺少 velocity graph 时计算它。遇到冲突会报错，需要显式解决，避免静默错配。

## 运行前必须核对

1. 图1原文没有提供全部对象的载入步骤，合并过程也包含人工修复版本。请逐阶段检查；不要把六个脚本当作可无人值守的一键流水线。样本注释、双细胞列、UMAP 前缀和 SA 样本是否纳入均需按实际数据确认。
2. 图2 DE 保留原文“无法识别 CK1/CK2 时选前两个样本”和 pbDS 宽松重试逻辑。运行前确认样本身份与过滤策略；本次整理未重新决定统计方案。
3. 图2 PI 与图3候选脚本需要外部汇总/标准化 DEG 文件，原文没有提供完整生产链。请核对列名、比较方向、筛选阈值和未检验比较，不把缺失记录补作 0 DEG。
4. CK2 补全的 RDS、图3 CK reference RDS、QS 注释参考和旧模块表未附带。仓库不自动生成这些输入。
5. 图3默认 `BIOLOGICAL_REPLICATES_CONFIRMED = FALSE` 和 `BIOLOGICAL_DIRECTION_CONFIRMED = FALSE` 保持不变。确认真实独立重复和方向证据后再配置；P1/P2/P3 不自动证明三个离散生物学状态。
6. 图4 TF 热图描述的是 RNA 推断的候选 regulon，不能当作 ATAC/motif 活性证据。脚本可能下载 PlantTFDB 名单，需核对所用资源和基因版本。
7. Python 的默认细胞类型自动选择、core_id 提取规则和数据过滤逻辑沿用原文。重复 core_id 现在拒绝合并，需要样本信息辅助建立唯一键。
8. 脚本仍可能覆盖其既定输出位置中的同名结果。请为首次运行准备独立的项目数据副本/输出位置。

原文中的论文引用、方法适用性和数值结果未在本次代码整理中进行独立科学审计。
